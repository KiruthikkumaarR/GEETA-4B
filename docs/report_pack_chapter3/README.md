### 1.3 Preprocessing
1. **Problem bank:** generated per skill with a fixed seed (20260818), with answers computed in Python. Each problem has worked
   `solution_steps`, a 3-level `hint_ladder` and a `similar_worked` example with a different answer. QA checks: hints
   checked for answer leaks, no duplicates, numbers kept within scope. On 13 Oct 2026 an audit found and fixed 50 wrong answers
   (17 rounding, 13 place-value, 20 ordering) in every copy, including the training data.
2. **Homework PDFs → JSON** (`notebooks/02`): pages rendered at 170 DPI (`pypdfium2`) → transcribed by a vision-language model → validated
   against a strict Pydantic schema (question type, text, child answer, marks, teacher comments) → teacher review sheet →
   **anonymised** (names, class, dates removed). PII audit result: **0 events**.
3. **Dialogue building** (`notebooks/03`): problems are turned into multi-turn chat (child attempt → hint 1 → hint 2 → solved), plus
   refusal and re-engagement patterns. Thinking mode is off (`enable_thinking=False`) on every row; prompt tokens are masked during training.
4. **Vision:** CROHME images downscaled from 1366×768 to 640×360 (seed 42), with linearised LaTeX labels.

### 1.4 Anonymised examples
`1_dataset/examples/`: three bank problems, four training dialogues (bank tutor, refusal, re-engagement, GSM8K), ten
adversarial probes, and two synthetic handwriting images with their labels.

## 3. System

- **Repository:** `github.com/KiruthikkumaarR/GEETA-4B` (**private**; commit `1cf6003`). I can add team members as
  collaborators. Model weights and children's data are excluded from git on purpose.
- **Diagram:** `3_system/architecture.png` (editable `architecture.svg`). Part A is one tutoring turn; Part B is the
  data → training → serving pipeline.
- **Key design:** the model **reads** (OCR) and **phrases**; deterministic Python **decides correctness**. About 30 Year 1–3
  question types are parsed and solved exactly in Python, which also writes the hints. Anything Python cannot read goes to the
  model, whose reply must pass the verifier and a reply checker. A leak guard checks every reply.
- **Setup** (macOS, Apple silicon):
  ```bash
  python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
  ./third_party/llama.cpp/llama-server --model models/geeta-4b/geeta-4b-q4_k_m.gguf \
      --mmproj models/geeta-4b/mmproj-geeta-4b-f16.gguf --host 127.0.0.1 --port 8080 -c 16384 -ngl 99
  ./webapp/run_webapp.sh          # http://127.0.0.1:8090
  ./deploy/run_all_tests.sh       # quality + security + feature suites (~15 min)
  ```
  For production, background services are installed with `./deploy/install_services.sh`.
- **Demo:** the app runs on my Mac and is reached through a free Cloudflare tunnel, so **the link changes on every
  restart** (current: https://portland-pursuant-like-text.trycloudflare.com). Ask me for a demo login, a live
  walkthrough, or a screen recording. Screenshots: `3_system/screenshots/`.

### 4.2 Metric definitions
- **Wrong answers delivered:** the number of problems where the child would be told something false (an incorrect final answer passed
  to the tutor). Target 0.
- **In-scope accuracy:** the share of held-out problems where the system ends with a verified correct answer (exact Python path
  or model path + verifier, retries allowed). **First-attempt accuracy** counts only the first try.
  **Fallback rate:** the share of problems where the system safely declines ("let's check this one together") instead of answering.
- **Leaks delivered:** the final answer appears in a reply that reaches the child (digits, words, $/c and other
  reformulations). **Raw leaks blocked:** the model's draft contained the answer and the guard stopped it.
- **OCR character accuracy:** 1 − normalised edit distance between transcription and ground truth, averaged over images.
- **Hallucination checks** (each reply): ARITH (false calculation stated), FALSE_YES (praises a wrong answer), FALSE_NO
  (rejects the right answer), LEAK (says the answer before the child does). These count as hard failures. NUMBER is a soft flag: a number not
  in the question, which is reviewed by hand and is often a legitimate hint step.
- **Scorecard /100:** weighted axes (delivered correctness 20, in-scope solving 30, OCR 20, pedagogy/engagement 15,
  never-reveal 15), per `4_evaluation/criteria/rubric.md`.
- **Success criteria were pre-registered** on 1 Sep 2026 (`success_criteria.yaml`, SHA-256 `f9fa1887…`) and have not been changed since.

### 4.6 Limitations (please keep these in the report)
1. **The OCR gate was measured on synthetic, font-rendered "kid-style" handwriting**, not real children's handwriting. The proposal
   asked for a real-kid-handwriting held-out set, which has not been collected. *(Our internal `SERVING_CONFIG.md` wrongly says "real
   kid handwriting"; please use this pack's wording.)*
2. The 249-problem test set is synthetic (generated from ACARA descriptions). Real-worksheet results come from only 3
   worksheets.
3. Most of the accuracy gain comes from the deterministic Python tutor, not from fine-tuning. Model-only accuracy is 81.5%.
4. No learning outcome has been measured yet; the n = 2 pilot needs ethics approval and cannot support causal claims.

## 5. Changes from the proposal and reasons

| Area | Proposal (project brief) | Final | Reason |
|---|---|---|---|
| Who checks the maths | Model proposes, Python verifies each step | Python **solves and tutors** common question types; model only reads, and handles fallback | Testing showed model-written hints were sometimes wrong (e.g. accepting "$1 + 50c = 60"); the verifier only checked final answers, not hint wording |
| Data storage | "No recording, nothing saved" | Per-child **learning summary** + parent PDF stored locally; chats, photos, camera never stored | Parents and tutors needed a progress history and GEETA needed to remember past topics; ethics documents updated (HREC v2) |
| Accounts | None | Parent / tutor / admin sign-in, kid picture + PIN | Needed once data is stored; access control |
| Access | Family's own machine | Investigator's Mac, reached through an HTTPS tunnel | Parents wanted to see progress from anywhere |
| Adapters | Optionally two adapters (OCR / tutor) | One merged model; worksheet + story adapters tested and **rejected** | Worksheet adapter scored lower; one model is simpler to serve |
| Voice | Silero VAD + Whisper + Piper | Browser Web Speech (speech-to-text + text-to-speech) | Works on any device with no extra models and no audio leaving the browser |
| Sampling | temp 0.7–1.0, top-p 0.95 | Separate settings per call (tutor 0.4, OCR 0.1, verify 0.2) | Measured: greedy or high-temperature settings lowered accuracy (section 4.4) |
| WhatsApp | Business API delivery | Dry-run only | Needs a Meta business account; email covers the requirement |
| Engineering fixes found during the build | – | RMSNorm double-shift fix at GGUF export; thinking mode forced off; separate internal "work it out" prompt | Without these the exported model produced garbage, empty replies, or refused its own internal checks (documented in `STATUS.md`) |
| Answer key | Generated bank trusted | 50 bank answers corrected + generator fixed | Found when the Python tutor's answers were compared with the bank |
| Interface | Single board / chat UI | Six themed "worlds" with buddies; worksheet question picker | Feedback from user testing: plain UI felt "too AI"; whole-page OCR confused the tutor |

**Main technical choices:**
- A 4B model was chosen so it runs fully on one laptop, which keeps children's data local.
- LoRA was used because a full fine-tune does not fit in 48 GB.
- GGUF + llama.cpp give fast Metal inference with vision support.
- Deterministic Python is used for correctness because a zero-wrong-answer guarantee cannot rely on a 4B model.
